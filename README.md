# HFH Internal CRM Bot

Внутренний Telegram-бот для диспетчеров, курьеров и сотрудников прачечной. Клиентского интерфейса нет. Бот использует aiogram 3, асинхронный SQLAlchemy и SQLite.

## Запуск

Требуется Python 3.10 или новее и токен Telegram-бота от BotFather.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Укажите `BOT_TOKEN`, Telegram numeric IDs администраторов в `ADMIN_IDS` (через запятую) и контакт в `GEOCODER_USER_AGENT`. Затем запустите:

```bash
python main.py
```

SQLite-файл создаётся автоматически. Для постоянного хранения при контейнерном запуске подключите volume к файлу, указанному в `DATABASE_URL`. Запускайте один экземпляр бота: FSM хранится в памяти, а встроенное ограничение публичного Nominatim рассчитано на один процесс.

## Доступ и роли

Сотрудник отправляет `/start`; до одобрения ему недоступны рабочие обработчики. Все Telegram IDs из `ADMIN_IDS` имеют права Super Admin. Кнопки админ-панели: список сотрудников с изменением роли/отключением, ожидающие заявки с назначением роли, статистика заказов и сотрудников, а также последние 20 заказов с возможностью отмены. Панель открывается командой `/admin`. Новые запросы на доступ отправляются каждому настроенному администратору.

## Рабочие процессы

- **Диспетчер:** меню содержит «Новая заявка», «Поиск», «Заказы», «Проблемные», «На сегодня», «Сводка дня» и «Помощь». Создание начинается с телефона: если номер встречался в истории, можно переиспользовать имя и последний адрес. Далее укажите имя, проверьте улицу и дом через 2ГИС, выберите тип жилья и детали квартиры, дату, интервал забора и вещи; комментарий необязателен. Перед записью показывается итог, который можно подтвердить или исправить. Дата хранится типом `DATE` по Asia/Bishkek. Списки заказов и результаты поиска поддерживают пагинацию и карточки с последними событиями. Отменять заказ, менять адрес или дату можно в статусе «Новый» и после неудачной попытки; контакт и комментарий доступны в любом незакрытом статусе. Отмена требует причины и подтверждения. Проблемные заказы включают неудачные, просроченные, долго находящиеся в пути, неоплаченные доставленные и адреса без координат.
- **Курьер:** «Начать смену», затем отправьте геопозицию; задачи сортируются по расстоянию и не включают новые заказы с будущей датой забора. Включите live location для автоматических обновлений. Начало этапа атомарно закрепляет заказ за курьером; вручную назначенный заказ можно открыть или отклонить. Курьер может передать диспетчеру описание проблемы. Завершение смены предупреждает об активных заказах.
- **Прачечная:** `/order 15` или «Найти заказ», введите замеры свободным текстом (например, `Ковёр 3x4 м; шторы 4 шт.`), затем отметьте обработанный заказ готовым. Изменения статуса записываются в историю, диспетчеры получают уведомление о готовности.

Все роли могут отправить `/help`. Неизвестные сообщения и устаревшие inline-кнопки получают понятный ответ.

## Геокодирование и эксплуатация

Адрес диспетчер вручную сверяет через ссылку поиска 2ГИС; координаты улицы и дома геокодируются через Nominatim-совместимый endpoint в Bishkek, Kyrgyzstan. Встроено ограничение не чаще одного запроса в секунду. Сервис может не найти адрес, отказать или быть недоступен; создание заказа при этом продолжается, а заказ без координат отображается в конце списка. Ссылка 2GIS для курьера показывается только для геокодированного заказа. Для production следует настроить собственный/коммерческий геокодер с подходящими SLA и проверить условия использования выбранного endpoint; публичный Nominatim не является production SLA-сервисом.

Времена создания и событий записываются в UTC и отображаются в часовом поясе Asia/Bishkek. SQLite при запуске мигрирует старое текстовое поле `pickup_day` в поле даты `pickup_date`. Изменения заказа сохраняются в журнале событий; после доставки диспетчер может отметить оплату. Защитите `.env` и файл SQLite резервными копиями. FSM-состояния не переживают перезапуск; для многопроцессного/высокодоступного запуска замените `MemoryStorage` на Redis и согласуйте геокодирование между экземплярами. Учётные записи сотрудников хранят Telegram ID и рабочие данные заказов; ограничьте доступ к хосту и резервным копиям.
